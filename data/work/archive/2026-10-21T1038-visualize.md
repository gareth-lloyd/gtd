Risk and governance

  1. Silent-blast quadrant. Scatter of blast_radius against failure_visibility, point size reader count, colour
     hotel-user-editable, shape by model. The top-left corner is settings a hotel user can change that break many
     things and nobody notices. The sharpest single chart, and entries alone give it.
  2. Governance coverage UpSet. Sets are brand-governed, brand-final, named in a consistency rule,
     hotel-user-editable, admin-exposed. Intersections sized by key count, filterable by blast radius. The "none of
     the above, high blast" bar is the list of ungoverned powerful settings. The "brand-final and hotel-user-editable"
     bar is a contradiction worth a look. Entries plus the derived tags.
  3. Change frequency against who can change it. change_frequency against editability class: hotel user, staff, brand
     provider, onboarding only. High frequency plus staff-only is support toil and a self-serve opportunity.
     Hotel-editable plus set-once is UI clutter. Entries alone.

  Structure and coupling

  4. Dependency graph rooted at product flags. Settings, capabilities, vendors and flags as nodes, edges by kind,
     origin: inferred dashed, cross-model edges highlighted. Three things fall out: dependency hubs by in-degree,
     edges with no consistency rule behind them, and model-boundary leaks. _model.yaml gives the tree a root per
     product, so it can be a hierarchy rather than a hairball.
  5. Reader-map clustered matrix. Keys against apps or directories, cells coloured by reader count, both axes
     clustered. The clusters are the real config groupings, and where they disagree with the model boundaries you have
     a refactor argument. Also surfaces god-reader modules, exempt candidates, and dead columns as empty rows. Needs
     the live reader map.
  6. Flow-scope parity matrix. Keys against flows: legacy, v3, kiosk, tablet, new registration, from the
     scope-boundary claims. Each gap cell is a setting one flow silently ignores. Directly useful for the v3
     migration. Entries alone, but the flow label has to be extracted from claim text, so it argues for a structured
     scope field on a claim.
  7. Citation hotspots. Code files sized by how many entries cite them, against git churn of that file. The top-right
     corner is fragile hubs where one PR invalidates dozens of entries and the freshness comment fires constantly.
     Entries plus git log.

  Fleet overlays, using the registry as the oracle

  8. Impossible settings per PMS. Keys against capabilities from requires capability: edges, folded by vendor into
     which settings cannot work on each PMS. Overlay production: hotels on PMS X with setting Y on are guaranteed
     broken. Needs prod values.
  9. Edge-violation heatmap. requires and conflicts_with edges against brands, cell count is hotels where the edge is
     unsatisfied. Latent misconfiguration across the fleet, ranked by brand. The provider already computes satisfied
     per hotel, so the aggregation is the only new piece.
  10. Freshness horizon. Per model over time, entries whose cited files changed since verified_at_commit. Shows where
      the registry decays fastest and sets the re-investigation cadence.
